How a run works

  1. The executive agent plans the task and picks up to three active employees.
  2. Each employee returns a result; progress streams into the live run panel.
  3. If an employee requests a granted MCP tool, the run pauses. The approval card shows the server, employee, exact tool name, and arguments.
  4. Approving resumes the run; rejecting resumes it without contacting the remote server. Every external call still needs its own approval.

Company workspaces

Each workspace has its own employees, tools, runs, approvals, and connector tokens. Use the company switcher above the navigation to create a workspace for another company or to switch between them. Workspace settings edits the company name, branches, operator, and deletion.

Local safety boundary

There is no login, tenant isolation, or billing. The server binds to loopback and stores workspace state, pending approvals, and connector tokens in owner-only files under data/. Tokens are not encrypted. Do not place customer secrets in the workspace.

Demo mode (AGENT_FACTORY_DEMO=1) simulates every model and tool call, labels results as simulated, and never contacts a model or MCP server.
